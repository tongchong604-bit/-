# 试用版验证与实现记录

## 验证

- `npm ci --prefix dev --ignore-scripts`、`npm --prefix dev test`：22项采集/导出测试通过。
- `npm --prefix dev run browser`：离线真实Chromium页面运行提取、fetch、ZIP和管理页，触发浏览器保存；独立Python验证已下载ZIP的CRC、中文文件名和图片。
- 浏览器用例通过适配器提供Chrome扩展API：云机器受管理员策略限制，无法加载未打包扩展。因此不把离线管理页测试称为真实扩展安装或抖音端到端测试。
- 实际Win7/Chrome109、真实抖音页面和图片服务兼容性仍待用户试用。
- 开发测试需要Node.js、Python及Chrome/Chromium。浏览器测试默认使用`/usr/bin/chromium`，可用`CHROMIUM_PATH`指定。用户安装插件不需要这些开发工具。

## 审查结果

独立审查发现的四项问题均有先失败后通过的回归测试：可见验证弹窗必须阻止采集；补图新增内容不能沿用旧的完整标记；优先明确原图字段；排除嵌套其他笔记的配图。浏览器测试另发现并修复了fetch接收者绑定错误。

## 实现裁定

1. 使用已有隔离工作区和work分支，不额外创建worktree；隔离由云任务提供。
2. 云技能未提供本地脚本目录，手工保存相同任务账本；没有假称执行不存在的脚本。
3. 本次由主代理实现，独立代理做最后审查，减少协调。
4. ZIP默认20MiB分包，单图15MiB、一次图片总量100MiB，本地最多200篇/约4MiB元数据；超限时须分批或查看失败报告。
5. 声明最低Chrome109，聚焦Win7的最后官方版本；更旧版本不能安装。
6. 云端浏览器管理员禁止加载未打包扩展，用本地API适配器检验管理页；真实Chrome扩展API仍待用户安装确认。

## 暂缓的次要项

ZIP大小估算时仍会复制图片缓冲区，大批量可能增加CPU/内存开销；本版建议每次3～5篇，后续可优化为只读取字节长度并累计尺寸。

## 0.1.1修正

用户截图证明已显示图片的播放页仍无法匹配0.1.0限定的DOM根选择器，错误文案把布局不支持混同登录问题。修正错误提示，新增用户明确点选的单图采集（含背景图），并提供不含表单/正文/脚本/Cookie、清除URL查询参数的结构诊断，为实际账号主页批量适配提供必要证据。暂不宣称支持账号全量采集。

新增单元测试覆盖手动点选、外域和视频封面拒绝、可见验证页/其他笔记归属拒绝，以及诊断隐私。离线真实浏览器用例复现自动根识别失败，验证点击仅采集选中大图、Esc清理事件，并读取真实可见位置；Chrome消息仍用适配器。

0.1.1独立审查发现诊断路径可能包含认证标识；已新增先失败后通过的回归测试，排除隐藏认证/表单子树，限制公开链接路由、数字笔记ID，所有图片路径仅保留域名。最新扩展测试28/28通过；两份分发ZIP在最终修改后全部重新打包并逐条与源码核验。
